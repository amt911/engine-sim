# 3D View — Phase 1 (scene and camera) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 3D view of the moving engine (block, head, crank, rods, pistons, valves; rotary
housing and rotor) in the central panel, orbit/zoom camera, a 2D/3D toggle, automatic detail
levels and a frame-time bench.

**Architecture:** Pure, tested modules in `crates/engine-app/src/view3d/` build meshes (once per
engine definition) and per-frame instance transforms (from the `Snapshot`); a thin wgpu renderer
draws them into its own off-screen colour + depth target in `CallbackTrait::prepare` and blits
that texture in `paint`, so eframe's surface needs no depth buffer. Nothing touches the sim thread.

**Tech Stack:** Rust 2024, eframe/egui 0.37 (wgpu backend), `egui_wgpu::CallbackTrait`, wgpu (the
version eframe 0.37 re-exports as `eframe::wgpu`), `glam` 0.30 (new crate: vector/matrix maths;
named in the PR), WGSL.

**Spec:** `docs/superpowers/specs/2026-11-03-3d-view-design.md`

## Global Constraints

- 60 fps on the 5850U's integrated GPU at 1080p with all layers on, GPU time ≤ 4 ms/frame.
- UI-thread CPU for the 3D view ≤ 2 ms/frame, no allocation per frame in steady state.
- Meshes rebuilt only when the definition changes — never per frame.
- Sound untouched: the view never takes time from the sim thread or the audio.
- The scene is always derived from the `EngineDef`; no second source of truth for geometry.
- The 2D cross-section stays (toggle).
- Off-screen renders only (`egui_kittest` + `wgpu`), never a desktop capture.
- SI units internally; f32 is fine on the render side.

## Review Focus

1. Engine changed in the editor (cylinder count, layout, rotary ↔ piston) while the 3D view is
   open → meshes and instance buffers rebuilt once, no panic, no stale cylinder. Pinned in Task 5
   (`scene_rebuilds_when_the_definition_changes`).
2. A GPU without a usable wgpu device / the GL backend → the toggle falls back to 2D with a
   message instead of a crash. Pinned in Task 4 (`no_render_state_means_2d`).
3. Zero-size or minimised central panel → no zero-sized texture creation (wgpu panics on it).
   Pinned in Task 4 (`target_size_is_never_zero`).
4. Extreme camera input (huge scroll, pitch past the poles) → clamped, never NaN. Pinned in
   Task 1 (`orbit_clamps_pitch_and_distance`).
5. A one-cylinder engine and a 12-cylinder V → scene fits the view (camera frames the bounds).
   Pinned in Task 3 (`bounds_cover_every_part`).

### Task 2: Procedural meshes (pure)

**Files:** Create `crates/engine-app/src/view3d/mesh.rs`.

**Interfaces:**
- Produces: `#[repr(C)] #[derive(Clone, Copy, bytemuck::Pod, bytemuck::Zeroable)] pub struct Vertex { pub pos: [f32; 3], pub normal: [f32; 3] }` (bytemuck is already a dependency of egui/wgpu; add it explicitly to `engine-app` if not re-exported);
  `pub struct Mesh { pub vertices: Vec<Vertex>, pub indices: Vec<u32> }`;
  `pub fn cylinder(segments: u32) -> Mesh` (unit: radius 1, y from 0 to 1, capped);
  `pub fn cuboid() -> Mesh` (unit cube centred at origin, side 1, flat normals);
  `pub fn disc_with_hole` is NOT needed in phase 1 (YAGNI);
  `pub fn rotor(segments_per_flank: u32) -> Mesh` (Reuleaux-like triangle prism of unit circumradius, height 1, from the epitrochoid's inner envelope approximated by three circular arcs);
  `pub fn housing(e_over_r: f32, segments: u32) -> Mesh` (epitrochoid outline extruded, unit generating radius; same formula as `view::housing_point`, which moves to a shared `pub(crate) fn` in `view.rs` so both views use one copy).

### Task 3: Scene from definition + snapshot (pure)

**Files:** Create `crates/engine-app/src/view3d/scene.rs`.

**Interfaces:**
- Consumes: `engine_core::config::EngineDef` (`geometry.bore_m`, `crank_radius()`, `rod_m`, `clearance_volume()`, `piston_area()`, `rotor`), `layout.place(n)`, `layout.bank_angle_deg`, `intake_valve`/`exhaust_valve` diameters if present; `sim::Snapshot { crank_deg, cylinders: Vec<CylinderView> }`.
- Produces: `#[derive(Clone, Copy, PartialEq, Eq, Hash)] pub enum Part { Block, Head, Crank, Rod, Piston, IntakeValve, ExhaustValve, Housing, Rotor }`;
  `pub struct Instance { pub part: Part, pub model: glam::Mat4, pub color: [f32; 4] }`;
  `pub struct Scene { pub static_parts: Vec<Instance>, pub bounds: (Vec3, f32) }` built by `pub fn build(def: &EngineDef) -> Scene` (block, head, housing: no motion);
  `pub fn moving(def: &EngineDef, snap: &Snapshot, out: &mut Vec<Instance>)` — clears and refills `out` (no allocation once capacity is reached).
  Drawing choices (from the spec's "left to the builder", fixed here): cylinders along +x at a pitch of `1.2·bore`; bank axes tilted ±half the bank angle about x (bank 0 to −, bank 1 to +, as the 2D view); crank axis = x; piston pin height above the crank from the crank-slider (the same `piston_m` the sim reports: `CylinderView::piston_m` is distance below TDC, so pin height = `r + l − piston_m`); valves on the head face, lift along the bank axis from `intake_lift_m`/`exhaust_lift_m`.
- [ ] **Step 1: Failing tests (hand values):**
  - `inline4_cylinders_are_1_2_bores_apart`: inline4 preset, piston instances' x = 0, 1.2b, 2.4b, 3.6b (b = bore).
  - `a_piston_at_tdc_sits_r_plus_l_above_the_crank`: snapshot with `piston_m = 0` → piston model translation y = r + l (inline, so axis = +y).
  - `v8_banks_lean_45_degrees`: crossplane preset (90°): bank-0 piston at TDC at (·, (r+l)cos45°, −(r+l)sin45°) in the y–z plane (pick the sign the 2D view uses; write it by hand).
  - `bounds_cover_every_part`: for `single`, `inline4`, `lfa-v10`, `mazda-renesis` presets, every instance origin lies inside `bounds`.
  - `rotary_has_housing_and_rotor_not_pistons`: renesis → contains `Part::Housing` and `Part::Rotor`, no `Part::Piston`.
  - `moving_does_not_reallocate`: call `moving` twice into the same Vec; capacity unchanged after the first call.
- [ ] **Step 2:** Run → FAIL. **Step 3:** Implement. **Step 4:** Pass; sabotage the bank sign, see `v8_banks…` fail, restore. **Step 5:** Commit `feat(app): the engine's 3D scene from its definition`.

### Task 4: wgpu renderer (glue)

**Files:** Create `crates/engine-app/src/view3d/render.rs`, `crates/engine-app/src/view3d/shader.wgsl`.

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces: `pub struct Renderer` (pipelines, one vertex/index buffer per `Part` mesh, an instance buffer grown by doubling, off-screen colour `Rgba8UnormSrgb` + `Depth32Float` targets, blit pipeline); stored in `egui_wgpu::RenderState::renderer.write().callback_resources` (the documented pattern) by `pub fn install(rs: &egui_wgpu::RenderState, detail: Detail)`;
  `pub struct Frame3d { pub view_proj: Mat4, pub instances: Vec<Instance>, pub size_px: [u32; 2], pub def_version: u64 }` implementing `egui_wgpu::CallbackTrait` (`prepare`: rebuild meshes if `def_version` changed, upload instances, render to the off-screen target; `paint`: blit);
  `pub fn target_size(rect_px: [f32; 2]) -> [u32; 2]` (each side `max(1)`, rounded).
  Shading: Lambert with one directional light + 0.25 ambient; colours per part (block grey, pistons light grey, valves blue/orange as the 2D view's intake/exhaust colours, crank dark steel).
- [ ] **Step 1: Failing tests:** `target_size_is_never_zero` (`target_size([0.0, 0.4]) == [1, 1]`); `no_render_state_means_2d` (in `app.rs` tests: an app built without `render_state` reports 3D unavailable and draws 2D).
- [ ] **Step 2:** Run → FAIL. **Step 3:** Implement the renderer. **Step 4:** Tests pass; extend `render_screens` (off-screen kittest with wgpu) to save `target/screens/engine-3d-<preset>.png` for inline4, crossplane V8, LFA V10, Renesis; assert in-test that the 3D rect has > 5 % non-background pixels; look at the PNGs. **Step 5:** Commit `feat(app): render the engine in 3D with wgpu`.
